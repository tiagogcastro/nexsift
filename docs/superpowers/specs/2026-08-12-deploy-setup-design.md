# NexSift deploy setup design

Date: 2026-08-12

## Context

The product surface (`web/`) is ready but not deployed. Milestone 3 (real AWS) and the Vercel deploy are the next step. Two friction points block the deploy:

1. `@nexsift/schemas` is a plain folder resolved via tsconfig `paths` (outside the Vercel root directory). It works locally but is the most fragile link in the build chain.
2. There is no static PNG version of the app icon for external use (README, GPT Action logo, branding).

## Decisions

- **Schemas become a yarn workspace** (`@nexsift/schemas` with `exports` pointing to `.ts` sources). Resolution goes through `node_modules` symlinks; tsconfig `paths` mappings are removed. This is the canonical monorepo pattern for Vercel and will scale for Milestones 3 and 4.
- **PNG icons generated by script**: `web/scripts/generate-icons.mjs` renders `web/src/app/icon.svg` to `web/public/icon-32.png`, `icon-180.png`, `icon-512.png` using `sharp`. PNGs are committed. The App Router metadata conventions (`icon.svg`, `apple-icon.tsx`) stay unchanged.
- **AWS provisioned before Vercel**: bucket de conteúdo + IAM de leitura para o Vercel + Lambda de publicação com Function URL e token (Milestone 3 completo), seguido de seed com o primeiro post.
- **Vercel configurado via vercel.json + CLI**: Root Directory `web`, produção na branch `main`, previews por PR. Env vars de Production e Preview apontando para o bucket real (somente leitura). `NEXT_PUBLIC_SITE_URL` usa o URL `*.vercel.app` até haver domínio.

## Sequencing

1. Repo: schemas workspace + PNG icons (com commits convencionais).
2. Verificação local: lint, typecheck, test, build, smoke do bundle da lambda, MiniStack + dev.
3. AWS: credenciais, Terraform prod, seed, teste de leitura.
4. Vercel: vercel.json, link, env vars, branch main, deploy de produção.

## Risks

- esbuild pode tratar o workspace `@nexsift/schemas` como pacote externo no bundle da lambda. Verificação: grep no dist + smoke `require`. Fallback: `--packages=bundle` ou alias no esbuild.
- O texto do SVG renderizado pelo libvips (sharp) usa a fonte monospace disponível no sistema e pode divergir ~1px do render do browser. Checkpoint visual antes de commitar os PNGs.
- Sem domínio próprio, URLs canônicas usam `*.vercel.app`; troca posterior é só env var.
